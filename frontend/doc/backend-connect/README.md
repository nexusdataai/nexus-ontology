## Overview

The UI is a React SPA that connects to a Python FastAPI backend. The backend URL is resolved at **runtime** (not build time) from `config.json`, allowing the same build artifact to be deployed to any environment.

```
config.json (runtime)
  |
  v
configService.ts -> getConfig() -> { api: { baseUrl: "..." } }
  |
  v
All services read baseUrl:
  backendAuthService.ts  -> /api/v1/auth/*
  useRBAC.ts             -> /api/v1/rbac/*
  backendDebugService.ts -> /health, /api/v1/diagnostics/*
  wxccSimulatorService   -> /api/v1/simulator/*
  webexConnectorService  -> /api/v1/webex/*
  licenseService         -> /api/v1/license/*
  callProcessingJourney  -> /api/v1/journeys/*
  processedCallsService  -> /api/v1/calls/*
  ssmConfigService       -> /api/v1/config/*
```

**Key rule:** When `baseUrl` is empty (`""`), all API calls use relative URLs (e.g., `/api/v1/auth/login`). This means the request goes to the same origin as the UI, where nginx or CloudFront proxies it to the backend.

## Configuration Loading

### Priority Chain

The `configService.ts` loads configuration with this priority:

```
Local development (localhost detected):
  1. Environment variables (VITE_* from .env.local)
  2. /config.json (fetched at runtime)
  3. Built-in defaults

Production / Staging:
  1. /config.json (fetched at runtime, cache: no-store)
  2. Environment variables (baked at build time)
  3. Built-in defaults
```

### Loading Flow

```
App starts
  |
  v
configService.getConfig()
  |
  ├── Is localhost?
  |   ├── Yes: Load from VITE_* env vars
  |   |        If valid -> use env vars
  |   |        Else -> try config.json
  |   └── No: Fetch /config.json
  |            If valid -> use config.json
  |            Else -> try VITE_* env vars
  |
  v
mergeConfigs(source, defaults) -> AppConfig
  |
  v
Cache in memory (singleton)
  |
  v
All services call getConfig() and get cached result
```

### How Services Use Config

Each service loads the config once, then constructs API URLs:

```typescript
// backendAuthService.ts
private async ensureConfigLoaded(): Promise<void> {
  const config = await getConfig();
  this.baseUrl = config.api?.baseUrl || '';
}

// Then all API calls:
await fetch(`${this.baseUrl}/api/v1/auth/login`, { credentials: 'include' });
```

Some services (like `backendDebugService`) fetch `/config.json` directly instead of using `configService`, but the result is the same.

## Deployment Modes

### Mode 1: EKS (nginx proxy)

```
Browser -> ALB -> nginx (:8080)
                    |
                    ├── /            -> static files (React app)
                    ├── /config.json -> static file (from /usr/share/nginx/html/)
                    └── /api/*       -> proxy_pass http://backend-svc-internal:8000
```

**config.json:**
```json
{
  "api": { "baseUrl": "" },
  "dataSource": "api"
}
```

**How it works:**
- `baseUrl: ""` means all API calls use relative URLs: `/api/v1/auth/login`
- nginx matches `/api/*` and proxies to the backend ClusterIP service
- Same origin = no CORS, cookies work with `SameSite=Lax`
- Backend is never publicly exposed

**nginx.conf:**
```nginx
location /api/ {
    proxy_pass http://call-processing-prod-backend-svc-internal:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
}
```

### Mode 2: S3/CloudFront + ECS Backend

```
Browser -> CloudFront -> S3 (static files, config.json)
        -> ALB -> ECS Fargate (:8000)  (API calls)
```

**config.json** (generated by deployer and uploaded to S3):
```json
{
  "api": { "baseUrl": "https://api.myapp.example.com" },
  "dataSource": "api",
  "enableFallback": true
}
```

**Note:** No Cognito configuration in `config.json`. Authentication is entirely handled by the backend, which reads Cognito settings from SSM Parameter Store (`/{capability}/{env}/cognito/*`). The frontend only needs the backend API URL.
```

**How it works:**
- `baseUrl` is the backend ALB's public URL (e.g., `https://api.myapp.example.com`)
- All API calls go cross-origin to the ALB
- Backend must configure CORS (FastAPI middleware) to allow the CloudFront domain
- Cookies need `SameSite=None; Secure` for cross-origin
- `config.json` is generated from CloudFormation stack outputs and uploaded to S3

**Config generation flow:**
```
CloudFormation stacks deploy
  -> UIConfigGenerator reads stack outputs:
       frontend-cognito -> UserPoolId, ClientId, Domain
       backend-service  -> ServiceURL (ALB URL)
       backend-domain   -> ApiUrl (custom domain)
  -> Generates config.json
  -> Uploads to S3 bucket
  -> Invalidates CloudFront cache for /config.json
```

### Mode 3: Local Development (with backend)

```
Browser -> Vite dev server (:8080)
        -> Backend (:8000)  (direct, cross-origin)
```

**.env.local:**
```bash
VITE_API_BASE_URL=http://localhost:8000
VITE_BYPASS_AUTH=false
VITE_DATA_SOURCE=api
```

**How it works:**
- `VITE_API_BASE_URL` is set to the local backend
- Cross-origin calls to `localhost:8000`
- Auth bypass can be enabled to skip Cognito

### Mode 4: Local Development (no backend)

**.env.local:**
```bash
VITE_BYPASS_AUTH=true
VITE_DATA_SOURCE=json
VITE_ENABLE_FALLBACK=true
```

**How it works:**
- Auth bypass creates a mock Admin user
- `dataSource: 'json'` reads from local `/public/results/*.json` files
- No backend needed at all

### Comparison Table

| Aspect | EKS (nginx) | S3/CDN + ECS | Local + Backend | Local (no backend) |
|--------|------------|-------------|----------------|-------------------|
| `baseUrl` | `""` (empty) | `https://api.example.com` | `http://localhost:8000` | `""` or anything |
| Config source | Static `config.json` | Generated, uploaded to S3 | `.env.local` (VITE_*) | `.env.local` (VITE_*) |
| API routing | nginx proxy | Cross-origin to ALB | Cross-origin to localhost | Mock data / no calls |
| CORS | Not needed | Required | Browser allows localhost | N/A |
| Cookies | SameSite=Lax | SameSite=None; Secure | SameSite=Lax | Mock session |
| Auth | Backend Cognito | Backend Cognito | Backend Cognito (optional) | Bypass (mock Admin) |

## config.json Reference

The runtime configuration file served at the root of the application.

```json
{
  "version": "1.0.0",
  "api": {
    "baseUrl": "",
    "timeout": 30000
  },
  "dataSource": "api",
  "enableFallback": true
}
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `api.baseUrl` | string | `""` | Backend API URL. Empty = same origin (nginx proxy). |
| `api.timeout` | number | `30000` | Request timeout in ms. |
| `bypassAuth` | boolean | `false` | Skip authentication (dev mode). |
| `environment` | string | auto-detected | `development`, `staging`, or `production`. |
| `dataSource` | string | `"api"` | `"api"` (live backend) or `"json"` (mock files). |
| `enableFallback` | boolean | `true` | Fall back to mock data if API fails. |

**No Cognito fields.** All Cognito configuration (User Pool ID, Client ID, domain, redirect URIs) is stored in SSM Parameter Store and loaded by the backend at startup. The frontend authenticates entirely through backend API endpoints (`/api/v1/auth/*`), never talking to Cognito directly.

## Environment Variables (VITE)

Build-time variables set in `.env.local` or CI/CD. Prefixed with `VITE_` to be exposed to the browser.

| Variable | Default | Description |
|----------|---------|-------------|
| `VITE_API_BASE_URL` | `""` | Backend API URL |
| `VITE_API_TIMEOUT` | `30000` | Request timeout (ms) |
| `VITE_BYPASS_AUTH` | `false` | Skip auth (`true`/`false`) |
| `VITE_DATA_SOURCE` | `api` | Data source (`api` or `json`) |
| `VITE_ENABLE_FALLBACK` | `true` | Enable mock data fallback |

**Note:** No Cognito variables needed. The frontend does not configure Cognito directly - the backend handles all Cognito configuration via SSM. In production (S3/CDN), VITE variables are baked into the JavaScript bundle at build time. For runtime configuration, use `config.json` instead.

## Service Connection Patterns

### Pattern 1: configService (most services)

```typescript
import { getConfig } from '@/services/configService';

const config = await getConfig();
const baseUrl = config.api?.baseUrl || '';

// API call
const response = await fetch(`${baseUrl}/api/v1/endpoint`);
```

**Used by:** `backendAuthService`, `dashboardDataProvider`, `useRBAC` hook

### Pattern 2: Direct config.json fetch (some services)

```typescript
const response = await fetch('/config.json');
const config = await response.json();
const baseUrl = config.api?.baseUrl || '';
```

**Used by:** `backendDebugService`, `wxccSimulatorService`, `webexConnectorService`, `licenseService`, `callProcessingJourneyService`

### Pattern 3: useConfig hook (React components)

```typescript
const { config, loading } = useConfig();
const baseUrl = config?.api?.baseUrl || '';
```

**Used by:** `useRBAC` hook

### Authentication Patterns

| Service | Auth Method | Cookie | Description |
|---------|-----------|--------|-------------|
| `backendAuthService` | `credentials: 'include'` | Yes | Session cookies |
| `useRBAC` | `credentials: 'include'` | Yes | Session cookies |
| `backendDebugService` | Custom headers | No | API key header |
| `wxccSimulatorService` | Custom headers | No | API key header |
| `webexConnectorService` | None visible | No | API key or session |
| `licenseService` | Custom headers | No | API key header |
| `processedCallsService` | Bearer token | No | Via apiClient |
| `ssmConfigService` | Bearer token | No | Via apiClient |

## Config Generation (Deployer)

### For S3/CDN + ECS Deployments

The deployer generates `config.json` automatically from CloudFormation stack outputs.

**Python service:** `nexus-deployer/backend/app/services/ui_config_generator.py`

```
CloudFormation Stacks
  |
  ├── frontend-regional -> S3BucketName
  ├── backend-service -> ServiceURL (ALB URL)
  └── backend-domain -> ApiUrl (custom domain, preferred)
  |
  v
UIConfigGenerator.generate_and_deploy_config()
  |
  ├── Build config.json with API URL only
  |     { "api": { "baseUrl": "https://api.myapp.com" }, "dataSource": "api" }
  ├── Backup existing: config.json.backup.{timestamp}
  ├── Upload to S3: s3://{bucket}/config.json
  |     Content-Type: application/json
  |     Cache-Control: no-cache, no-store, must-revalidate
  └── Invalidate CloudFront: /config.json
```

The generated `config.json` only needs the backend API URL. Cognito configuration is stored in SSM Parameter Store and loaded by the backend at startup - the frontend never configures Cognito directly.

**API URL resolution priority:**
1. `backend-domain` stack -> `ApiUrl` (custom domain like `https://api.myapp.com`)
2. `backend-service` stack -> `ServiceURL` (ALB URL like `https://alb-xxx.elb.amazonaws.com`)
3. `backend-service` stack -> `ApiEndpoint`
4. `backend-service` stack -> `ApiGatewayUrl`

**Shell script (manual):** `nexus-deployer/deploy/scripts/generate-ui-config.sh`

```bash
# Generate and upload config.json
./deploy/scripts/generate-ui-config.sh \
  --capability call-processing \
  --environment prod \
  --region ap-southeast-1
```

### For EKS Deployments

No config generation needed. The default `config.json` with `baseUrl: ""` is included in the Docker image at build time. nginx handles the proxying.

### For Local Development

Developers edit `.env.local` or `public/config.json` manually.

## Troubleshooting

### API calls returning 404

**Check:** Is the backend running? Is `baseUrl` correct?

```bash
# EKS: Check backend pods
kubectl get pods -n call-processing-prod | grep backend

# S3/CDN: Check ALB URL
curl https://api.myapp.example.com/health
```

### CORS errors in browser console

**Cause:** Frontend on one origin, backend on another, without CORS headers.

**Fix:** This only happens in S3/CDN + ECS mode. The backend must allow the CloudFront domain:
```python
# FastAPI CORS middleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.myapp.example.com"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

In EKS mode, nginx proxy makes everything same-origin, so no CORS is needed.

### Cookies not being sent

**Check:** `credentials: 'include'` in fetch calls? Cookie `SameSite` attribute correct?

- EKS (same origin): `SameSite=Lax` works
- S3/CDN (cross-origin): Needs `SameSite=None; Secure`

### config.json not updating after deployment

**Check:** CloudFront cache. The deployer invalidates `/config.json` after upload, but propagation takes ~30 seconds.

```bash
# Manual invalidation
aws cloudfront create-invalidation \
  --distribution-id EXXXXX \
  --paths "/config.json"
```

### "Failed to fetch config.json"

**Check:** Is `config.json` present in the deployment?

```bash
# EKS: Check inside nginx container
kubectl exec -n call-processing-prod deploy/call-processing-prod-frontend -- ls /usr/share/nginx/html/config.json

# S3: Check in bucket
aws s3 ls s3://my-frontend-bucket/config.json
```

### Service using wrong baseUrl

**Debug:** Open browser DevTools Console. The config service logs its source:

```
═══════════════════════════════════════════════════════════════
🔧 CONFIGURATION SOURCE: config.json
📁 Reading configs from: /public/config.json (runtime config)
═══════════════════════════════════════════════════════════════
📋 Config summary: { apiBaseUrl: "https://api.example.com", ... }
```
